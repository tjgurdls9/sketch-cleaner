## 사용자가 확정한 기준

- **남김:** 도해선, 봉제 점선(검정·파랑), 봉제 끝 빗금, 지퍼 물결선과 지퍼 끝 빗금, 벨트고리·주머니 같은 닫힌 세부.
- **지움:** 가위표(검정·빨강), 빨간 체크·화살표, 검은 지시선과 화살표, 파란 실선(벨트 자리 등), 도해 안 글씨.
- **도해 밖**은 자동으로 지운다(기존 동작).
- **도해 안**은 디자인일 수 있으므로 자동으로 지우지 않는다. 빨간 선택으로 잡아 두면 사람이 '표시 지우기'로 뺄 것을 빼고 Delete로 지운다. 사용자는 "조금 과하게 잡아 놓고 나중에 빼는" 쪽을 원한다.
- 학습은 쓰지 않는다. 정해진 규칙으로만 판단한다. 사용자가 학습을 명시적으로 거부했다.

## 동작 방식

### 즉시 편집 (`src/renderer/main.ts`, `src/core/engine.ts`)
- 지우개 획, 사각·펜·올가미 선택, Delete 채우기는 Worker로 보내지 않고 메인 스레드에서 엔진을 바로 실행한다(`applyNow`). Worker를 쓰면 스냅숏 전체를 양방향으로 복제해야 해서 실제 계산보다 느리다.
- 맥 12MP 기준으로 지우개 한 획은 24~49ms, 사각 선택 Delete는 57~66ms 걸렸다.
- 자동 정리, 회전, 자르기, 후보 적용은 그대로 Worker로 처리한다.

### 양식 표 분리 (`src/core/ruled.ts`)
- 도해가 양식 테두리에 닿으면 표와 한 덩어리가 되어 함께 지워지던 문제를 막는다.
- 큰 표 덩어리에서 ±2° 안의 긴 수평·수직선을 찾는다(기울기 허프 변환, 연속 구간만 인정).
- 찾은 선 가운데 **옆 도해의 펜 굵기(상위 사분위수)의 80%보다 가는 선**만 인쇄된 표 선으로 보고 뺀다. 남은 조각은 다시 도해 후보로 따진다. 그래서 자를 대고 그린 청바지처럼 굵은 직선 도해는 그대로 남는다.
- 스캔 테두리나 검은 띠처럼 꽉 찬 검은 영역은 선 찾기에서 제외한다.

### 도해 안 후보 (`src/core/marks.ts`의 `findAnnotationInk`, `src/core/automatic.ts`의 `figureCandidates`)
1. 도해 영역(겹치는 영역은 하나로 합침)의 잉크를 중심선 그래프로 바꾼다. 세선화 후 짧은 조각은 합치고, 갈림 없이 이어지는 노드도 합친다.
2. **남김 판정:** 펜 굵기 24배 이상 이어지는 선(외곽선은 40°까지 꺾여도 하나로 이어 봄), 점선, 선을 가로지르고 반대편에서 끝나는 짧은 직선(빗금), 좌우로 흔들리는 긴 선(지퍼 물결). 단, 글씨 영역 안에 있는 조각은 빗금이나 물결로 보호하지 않는다.
3. **가위표:** 빗금으로 남긴 획 가까이에 그 획이나 도해선에 붙은 곡선·고리가 있으면 가위표로 보고 후보로 바꾼다.
4. **후보:**
   - 글씨 영역(검출 박스를 펜 한 획만큼 넓힘)에 35% 이상 걸친 조각과, 거기에 붙은 획
   - 글씨에서 출발해 도해에 닿는 지시선과 화살촉
   - 글씨 없이 그려진 화살표
   - 아무 선에도 닿지 않은 작은 덩어리
   - 색 실선(단, 검은 선 바로 옆을 따라가는 색 봉제선은 남김)
   - 위 남김 판정에 걸리지 않는 나머지 짧은 조각
5. **후보에서 제외:** 닫힌 고리 위의 조각(벨트고리, 주머니, 허리단 끝), 두 도해선을 잇는 조각, 길게 혼자 있는 직선(봉제 구간), 선에서 비스듬히 뻗은 빗금 모양 획, 분석 영역 가장자리에서 잘린 조각.
6. 후보 픽셀은 `deleteMask`에만 추가하고 픽셀은 그대로 둔다. 화면은 후보가 있으면 `review` 상태("도해 안의 지울 후보를 빨간색으로 골라 두었습니다")를 띄우고 빨간 표시를 켠다.

### 조정 값
- 모두 `MARK_RULES`(`marks.ts`), `PRINTED_RULE_SHARE`·`TEXT_MASK_GROWTH`(`automatic.ts`), `RULED_MIN_*`(`ruled.ts`)에 모여 있다.
- 길이는 펜 굵기 배수로 잰다. 펜 굵기는 중심선에서 잰 두께의 중앙값이다.
- 너무 많이 지워지면 `sweepLine`을 낮추거나 `textShare`를 올린다. 덜 지워지면 반대로 한다.
- 값을 바꾸면 반드시 아래 '실제 작업지로 확인'을 다시 한다. 합성 테스트만으로는 부족하다.

## 검증 상태

- vitest 97개 통과. 커버리지는 전체 91.5%, `marks.ts` 95.5%, `ruled.ts` 98.8%, `automatic.ts` 97.8%.
- 각 규칙은 RED 테스트를 먼저 커밋하고 GREEN으로 고쳤다(`tests/marks.test.ts`, `tests/photoshop-tools.test.ts`, `tests/auto-review.test.ts`).
- Mac 실기 E2E 3개 통과: `imported garment`, `local AI`, `photoshop-style`(12MP, 실제 마우스·키).
- Windows CI는 #9, #10, #11 모두 통과했다(설치 앱 E2E 포함).
- 실제 작업지 4장(사용자 카카오톡 사진, 치마, 청바지, 재킷)은 Delete 후 미리보기를 눈으로 확인했다. 사진은 사용자 자료라 저장소에 넣지 않았다.

## 실제 작업지로 확인하는 법

저장소에는 평가 스크립트가 없다. 지난 작업에서는 무시 폴더 `.scratch/`에 임시 스크립트를 두고 썼다.

1. `src/main/ai.ts`를 CJS로 빌드해 `detectTextMask(pixels, 'dist/models/text-det.onnx')`로 글씨 마스크를 만든다. 모델은 `npm run build` 뒤 `dist/models`에 있다.
2. `autoCleanDraft(createSnapshot(pixels, 'b'), undefined, mask)`를 돌린다.
3. 원본 위에 `deleteMask` 픽셀을 분홍으로 칠한 그림과, 그 픽셀을 흰색으로 지운 그림을 만들어 비교한다.

이 과정을 `scripts/`에 정식 도구로 만들어 두면 다음 조정이 쉬워진다(아래 남은 일 참고).

## 알려진 한계

- 검은 지시선과 검은 가위표는 일부만 잡힌다. 글씨 모델이 놓친 손글씨 조각(세로 1/4" 등)이 일부 남는다.
- 넉넉하게 잡기 때문에 허리 개더, 재킷 단추 표시, 짧은 디자인 선이 후보에 들어갈 수 있다. 사용자가 원한 동작이지만 확인이 필요하다.
- 지퍼 물결선이 직선 위에 겹쳐 그려진 구간은 직선을 끊지 않고는 나눌 수 없어서 그대로 둔다.
- 실제 작업지 기준 자동 정리는 0.4~1.8초 걸린다(글씨 검출 0.1~0.3초 별도).
