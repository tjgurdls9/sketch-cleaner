## 0.2.0 자동 초안

- RED 체크포인트 `6d9c870`: 원본에 실제 필기·표·붉은 화살표가 포함된 입력의 자동 제거/도해 보존, 보호 혼합, 저확신 무변경, 결정성/불변성, 20MP 입력의 5개 테스트가 미구현 `auto-clean` 작업으로 실패했다.
- 메인 리뷰에서 기존 삭제 마스크의 재적용과 도해 내부 붉은 색상 삭제를 발견해 엔진 담당에게 반환했다. 자동 선정 범위로 적용을 제한하고 내부 색상을 보존하는 회귀 검사를 추가해 통과했다.
- 화면 재그리기는 같은 DOM 측정 조건(1200×800, 5000×4000 입력, 12회)에서 객체 할당을 줄인 전후를 비교했다. 실제 Windows 사용자 PC의 지연 검증과 구분한다.
- Windows 실행 14에서 기존 전체 여정과 새 자동 제거/도해 보존 검사는 통과했지만, 새 테스트가 작은 창에서 숨겨진 헤더 저장 버튼을 눌러 중단됐다. 새 여정의 창 크기를 명시해 실제 보이는 버튼으로 재검증한다. 자동 처리 실패로 분류하지 않으며 전체 여정 통과도 주장하지 않는다.
- 실행 15에서는 자동 정리 한 단계 undo/redo까지 통과한 뒤 삭제 도구의 선택자가 버튼과 캔버스를 함께 찾아 중단됐다. 버튼 선택자를 한정하고 도구 전환이 캔버스에 버튼용 상태를 붙이지 않는 회귀 검사로 보완한다.

아래는 0.1.0 기록이며, 0.2.0 최종 실행 결과는 인수 기록의 별도 항목을 따른다.

## 여정과 검증 매핑

| 대기 중 편집 가능, 기준 변경 결과는 차단 | 현재 작업 버전만 달라도 stale-basis를 반환한 Node assert 실패 | ui-state: 작업 버전 차이는 허용, 기준/요청/프로젝트 차이는 차단 |
| 긴 브러시 스트로크 | 전체 경계×모든 구간 방식의 계산량을 코드 검토로 지적 | 구간별 최대 커버리지, 500점 대각선의 강도 누적·시간 회귀 |

| 복구 후 다시 저장 실패 | 손상된 현재 포인터가 마지막 정상 백업을 덮는 경로를 검토에서 지적 | 복구→포인터 교체 실패→다시 정상 프로젝트 열기 |
| 다른 폴더 저장으로 복구 | UI가 원래 위치 재저장 성공을 요구하고 backend가 원래 root를 경유하는 문제 | renderer: 저장 실패 상태에서도 Save As, storage: 기본 root 쓰기 실패 주입 후 새 폴더에 직접 기록 |
| 프로젝트 열기 중 작업 보존 | 지연된 IPC 응답이 새 편집을 덮는 경로, 가드 추가 후 첫 사진 열기 회귀도 DOM에서 검출 | 지연 open 동안 tone 편집→응답 뒤 현재 작업 보존 |
| 요청·후보 손상 격리 | 부속 파일 하나로 정상 작업 리비전까지 열 수 없는 경로 | 두 포인터 모두 부속 기록을 가진 상태에서 부속 손상→현재 이미지·마스크 유지 |
| 요청 파일 크기 일치 | guide와 snapshot 크기를 별도로만 검사하는 경로 | 크기 불일치 거부, 프로젝트 리비전·요청 폴더에 부수 효과 없음 |

모든 실패가 RED 커밋으로 남은 것은 아닙니다. 최초 엔진/저장 테스트 체크포인트는 커밋으로 보존했고, 이후 독립 검토와 통합에서 발견한 실패는 본 문서·테스트·담당 handoff로 기록합니다. 테스트 설정 오류나 DOM 모의 직렬화의 realm 문제를 제품 버그의 RED 증거로 계산하지 않습니다.

기본 여정 DOM 테스트는 실제 renderer와 엔진 함수를 사용하며, Canvas·Worker 메시지 전달·DesktopAPI는 대역입니다. 실제 파일 I/O는 storage 테스트가 검증합니다. 이 조합을 실제 Windows 사용자 조작 인수로 대체하지 않습니다.
