# 인수 및 보안 검증 기록

## 0.3.0 로컬 AI 검증

사용자 확정: 원본 확인 후 자동 정리 버튼을 누른다. AGY 브랜치를 병합하지 않고 main 0d6dd6c에서 재구현했다.

- 타입·앱/테스트/E2E lint·공백 검사 통과. 10개 파일 72개 테스트 통과. 계측 대상 문장88.26%, 분기82.94%, 함수91.20%, 줄95.23%; ai.ts와 ai-manager를 포함하며 전체 renderer/main·Electron 부팅 계측은 아니다.
- 공식 RapidOCR v3.10.0 PP-OCRv4 mobile 모델의 출처·Apache-2.0·SHA-256을 확인했다. ONNX Runtime 1.30.0 MIT 및 제3자 고지도 함께 배포한다. 모델은 빌드 단계에서 검증해 포함하고 앱 실행 중 다운로드하지 않는다.
- 실제 모델로 합성 영문/한글 글씨 양성 검출 및 제거, 도해·봉제선·단추 보존, 기존 선택 범위와 독립된 적용, 완전/부분 보호, 입력 불변을 확인했다. 배포 형식 CJS와 실제 Node Worker의 추론/취소도 실행 검증했다.
- DOM에서 원본 미리보기, 두 단계 진행/취소, 실패·재시도, 늦은 응답 차단, 전체 파이프라인 한 단계 undo/redo, 저장 재개를 확인했다. 원본 이미지 파일과 기존 저장/복구 형식은 유지한다.
- AI IPC는 양수 크기·25MP·RGBA 길이·UUID·출력 마스크를 검증하고 동시 작업을 하나로 제한한다. 메인과 별도 스레드에서 실행하며 취소/60초 제한/창 종료 시 작업을 종료한다. 모델은 고정 앱 경로와 해시를 사용한다.
- 설치 앱의 실제 AI 실행은 해당 PR의 Windows test build/검증 자료를 최종 근거로 한다. native DLL과 ASAR 밖 모델 해시 검사, 실제 추론→직접 수정→PNG→재시작 검사가 포함된다.

미검증: 실제 업무 사진/손글씨/모든 의류 형식의 정확도, Windows11 실기기/DPI/20MP 체감 성능, 이전 버전에서의 실기기 업데이트, 코드 서명. 개발 Mac의 자동 GUI 실행은 창 생성 전 SIGABRT로 중단되어 성공으로 계산하지 않는다.


## 0.2.0 자동 정리 초안 검증

확정 여정은 **사진 선택 → 자동 정리 → 사용자 직접 수정 → 확인 및 저장**이다. 학습 모델을 추가하지 않은 로컬 휴리스틱 초안이며, 실제 업무 사진의 자동 처리율을 검증한 버전은 아니다.

- 로컬: 타입 검사, 앱/테스트/E2E lint, 빌드, `git diff --check`, 6개 파일 57개 테스트 통과. 계측 대상 문장 87.12%, 분기 81.87%, 함수 90.06%, 줄 94.73%. 계측 범위는 기존 핵심 모듈과 automatic.ts이며 renderer/main·Electron 부팅 전체 커버리지가 아니다. `npm audit` 취약점 0.
- 인수 자동 검사: 원본에 포함된 분리 필기/표/붉은 표시 제거, 앞뒤 도해·분리 내부 디테일·도해 내부 색상 유지, 완전/부분 보호, 기존 수동 선택 재적용 방지, 반복 실행 안정성, 저확신 무변경, 입력 배열 불변. DOM에서 자동 시작/취소/기존 프로젝트 재열기 미실행과 기존 수동 편집 경로를 확인했다.
- 성능 관찰(개발 Mac): 20MP 엔진 단독 무변경 67.6ms/+8.5MiB RSS, 변경 235.6ms/+144.1MiB RSS. Worker 복사·IPC·화면·저장 시간은 제외한다. 같은 1200×800 DOM/Canvas 대역의 12회 가열 측정에서 프레임 중앙값은 DPR1 16.2→7.9ms, DPR2 59→30.2ms였다. GPU나 실제 사용자 PC 결과가 아니다.
- 저장 비용 관찰(개발 Mac, 20MP): 생성 약 573ms, 마스크 저장 약 1,122ms, 프로세스 최대 RSS 약 1.8GB. 안전한 재읽기/원본 검증을 유지했으며 대형 사진의 저장 지연과 메모리 부담은 남아 있다.
- 보안: 새 패키지·모델·원격 호출·IPC 권한·파일 형식 변경 없음. 자동 처리는 기존 제한 Worker에서 실행하며 취소/오류 시 가져온 프로젝트를 보존한다. 원본/기준 이미지와 저장 검증 경계는 유지했다.
- Windows 0.2 설치 앱 검증의 실행 번호·결과는 이 변경 PR의 Windows test build 검사와 첨부 검증 자료를 기준으로 확인한다. 실제 Worker/IPC/파일 저장을 사용하는 자동 초안→직접 수정→undo/redo→PNG→재실행/최근 작업 흐름을 추가했다. 아래 Windows 실행 번호는 0.1.0 이력이다.

미검증: 실제 의류 작업 사진의 정리 품질, 겹친 필기 복원, Windows 11 실기기/DPI/20MP 체감 성능, 0.1→0.2 실기기 업데이트, 코드 서명. 오인식은 실행 취소·기준 복원 후 직접 수정한다. 도해 내부/겹친 표시와 기존 수동 선택 범위는 보수적으로 남을 수 있다.

## 보안 검토

- renderer Node 통합 비활성화, contextIsolation·sandbox·webSecurity 활성화.
- CSP는 로컬 스크립트/스타일만 허용. 네트워크 연결, frame, object, form, base 삽입 차단. 임의 새 창·리디렉션·다른 페이지 이동 차단.
- IPC는 등록된 창의 main frame과 정확한 로컬 진입 URL을 검사. preload는 고정 메서드만 노출하며 renderer에 범용 파일·shell 실행기를 주지 않음.
- 일반 이미지 확장자와 시그니처·실제 디코딩 형식, 50MB/25MP 상한, 단일 페이지, EXIF 방향을 검사. 외부 입력과 내부 무손실 PNG의 바이트 상한을 분리.
- 프로젝트 버전, UUID, 크기, RGBA·마스크 배열, 보호 픽셀, 원본 해시, 고정 참조 경로를 검사. 폴더 이탈·심볼릭 링크 참조를 거부.
- 새 리비전의 이미지/마스크를 다시 읽어 검증한 후 현재 포인터를 교체. 손상된 현재 포인터를 정상 이전 포인터에 덮어 백업하지 않음. 복구 중에도 기존 정상 리비전 삭제 없음.
- 후보·요청이 손상되어도 정상 작업 이미지와 마스크를 열 수 있으며, 손상 파일의 사용은 오류로 거부. 사진 필기·요청 문구·후보를 명령으로 실행하지 않음.
- 앱은 계정 비밀번호·토큰·API 키를 저장하지 않음. 원격 로그·분석·자동 업로드·다운로드 감시 없음.
- 의존성 취약점 검사에서 Sharp/Vitest의 발견 항목을 수정 버전으로 갱신하고 재검사. 패키징에서 native 모듈과 부속 libvips 라이브러리를 ASAR 밖에 포함하도록 수정.

검토 중 발견한 자르기 undo 저장 거부, 복구 후 포인터 손실, Save As의 실패 위치 재사용, 비동기 프로젝트 전환 중 편집 손실, 요청 guide 크기 불일치, 좁은 화면에서 핵심 버튼 숨김은 담당자에게 반환해 수정하고 재검증했습니다.

## 실행 환경 제한과 알려진 한계

- 개발 호스트의 Electron과 headless Chrome이 macOS `_RegisterApplication` 단계에서 SIGABRT로 종료되어 GUI/E2E 실행 검증을 완료하지 못했습니다. 앱 코드 로드 이전 실패이며 성공으로 처리하지 않았습니다.
- `npm run test:e2e`: 로컬 실행은 실패했지만 Windows Server 2025 CI에서 실제 설치된 앱 E2E 및 설치/같은 버전 재설치/제거 시 기본 데이터 폴더 보존 검사는 통과했습니다.
- 개발 호스트의 실제 브라우저도 이 세션에서 기동하지 못했습니다. Windows CI 화면 캡처는 확인했으며, Windows 11 실기기·DPI·업무 사진의 시각 검수는 남아 있습니다.
- 취소 이력은 세션 내에서만 유지하며 메모리 예산 512MiB에 따라 오래된 이력이 잘릴 수 있습니다. 최소 직전 상태와 기준 변환은 일시적으로 예산을 넘을 수 있음.
- Worker 결과 버퍼는 전송하고 같은 기준 이미지는 공유하지만 입력 복사·후보·PNG 인코딩은 큰 메모리를 사용합니다. 20MP/25MP 실제 Windows 메모리·응답 시간은 측정하지 못함.
- 매 확정 편집 후 약 1.2초에 자동 저장을 시작합니다. **2초 안에 디스크 저장 완료를 보장하지 않습니다.** 사진 크기·요청 수·저장 장치에 따라 실기기 시험 후 조정 필요.
- 기본 저장 폴더를 쓸 수 없을 때 Save As는 새 폴더에 직접 기록합니다. 이때 기본 위치의 최근 목록 갱신은 실패할 수 있으므로 새 프로젝트의 표시 경로를 보관하고 ‘프로젝트 열기’로 열 수 있음.
- 전원 차단·물리 디스크 고장에 대한 보장은 하지 않습니다. 실제 프로세스 강제 종료/디스크 부족 검증은 위 표의 실기기 인수에 남아 있음.
- 실제 Plus 선행 품질 검증과 외부 처리 허용 확인이 제공되지 않았습니다. GPT 흐름은 선택적인 수동 전달이며 정밀 편집 품질·동일 해상도 반환을 보장하지 않음.
- Windows 설치 파일 코드 서명과 실무 인수는 완료하지 않았습니다. Windows CI의 서명 없는 테스트 설치 파일을 정식 배포로 표현하지 않음.
